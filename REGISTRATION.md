# Система регистрации

## Обзор

Система регистрации позволяет создать новый аккаунт школы единоборств (тенант) и автоматически создает владельца (OWNER) с полными правами доступа.

## Процесс регистрации

### 1. Frontend (Клиентская часть)

**Файл:** `client/src/pages/Register.tsx`

#### Шаги регистрации:

1. **Заполнение формы регистрации:**
   - **Название школы** (обязательно, минимум 2 символа)
   - **Имя владельца** (обязательно, минимум 2 символа)
   - **Фамилия владельца** (обязательно, минимум 2 символа)
   - **Email** (обязательно, используется для входа)
   - **Телефон** (необязательно, формат: +79991234567)
   - **Пароль** (обязательно, минимум 6 символов)
   - **Подтверждение пароля** (обязательно, должно совпадать)

2. **Клиентская валидация:**
   - Проверка всех обязательных полей
   - Валидация формата email
   - Валидация формата телефона (если указан)
   - Проверка минимальной длины пароля
   - Проверка совпадения паролей
   - Очистка данных (trim, lowercase для email)

3. **Отправка запроса:**
   - Данные отправляются через `AuthContext.register()`
   - Показывается индикатор загрузки
   - Обрабатываются ошибки с переводом на русский язык

4. **Успешная регистрация:**
   - Пользователь автоматически авторизуется
   - Токен сохраняется в localStorage
   - Происходит редирект на `/dashboard`

### 2. Backend API

**Эндпоинт:** `POST /api/auth/register`

**Файлы:**
- `src/routes/auth.ts` - маршрут
- `src/controllers/authController.ts` - контроллер
- `src/services/authService.ts` - бизнес-логика

#### Валидация запроса:

Используется Joi схема валидации:
```typescript
{
  tenantName: string (2-100 символов, обязательно)
  email: string (валидный email, обязательно)
  password: string (минимум 6 символов, обязательно)
  firstName: string (2-50 символов, обязательно)
  lastName: string (2-50 символов, обязательно)
  phone: string (опционально, формат: +79991234567)
}
```

#### Процесс обработки:

1. **Генерация поддомена:**
   - Автоматически генерируется из названия школы
   - Транслитерация кириллицы в латиницу
   - Удаление спецсимволов, замена пробелов на дефисы
   - Приведение к lowercase
   - Ограничение длины до 50 символов
   - Проверка уникальности (если занят, добавляется суффикс -1, -2, и т.д.)

2. **Проверка уникальности email:**
   - Проверяется, не зарегистрирован ли уже пользователь с таким email
   - Если email занят, возвращается ошибка

3. **Хеширование пароля:**
   - Пароль хешируется с помощью bcrypt (12 раундов)
   - Оригинальный пароль никогда не сохраняется

4. **Создание тенанта и пользователя (транзакция):**
   - Создается запись `Tenant` в базе данных
   - Создается запись `User` с ролью `OWNER`
   - Связывание пользователя с тенантом через `tenantId`
   - Все выполняется в одной транзакции (либо все успешно, либо откат)

5. **Генерация JWT токена:**
   - Создается токен доступа для автоматической авторизации
   - Токен содержит: userId, email, role, tenantId

6. **Возврат результата:**
   ```json
   {
     "success": true,
     "data": {
       "user": {
         "id": "...",
         "email": "...",
         "firstName": "...",
         "lastName": "...",
         "role": "OWNER",
         "tenantId": "..."
       },
       "tenant": {
         "id": "...",
         "name": "...",
         "subdomain": "..."
       },
       "token": "jwt_token_here"
     },
     "message": "Tenant registered successfully"
   }
   ```

## Особенности

### Автоматическая генерация поддомена

Поддомен генерируется автоматически из названия школы:

**Примеры:**
- "Школа единоборств" → "shkola-edinoborstv"
- "Dragon Academy" → "dragon-academy"
- "Школа №1" → "shkola-1"

**Алгоритм:**
1. Транслитерация кириллицы в латиницу
2. Приведение к lowercase
3. Замена пробелов и спецсимволов на дефисы
4. Удаление лишних дефисов
5. Ограничение длины до 50 символов
6. Проверка уникальности (если занят, добавляется суффикс)

### Безопасность

- **Пароли:** Хешируются с помощью bcrypt (12 раундов)
- **Валидация:** Двухуровневая (клиентская и серверная)
- **Транзакции:** Использование транзакций БД для целостности данных
- **JWT:** Токены для безопасной аутентификации

### Обработка ошибок

**Типичные ошибки:**
- `Email is already registered` → "Этот email уже зарегистрирован..."
- `Subdomain is already taken` → "Ошибка создания аккаунта..."
- `Validation error` → "Проверьте правильность заполнения..."

## Поток данных

```
[Frontend Form] 
    ↓
[Client Validation]
    ↓
[AuthContext.register()]
    ↓
[API Service: POST /api/auth/register]
    ↓
[Auth Controller: validateRegister middleware]
    ↓
[Auth Service: registerTenant()]
    ↓
[Generate Subdomain]
    ↓
[Check Email Uniqueness]
    ↓
[Hash Password]
    ↓
[Database Transaction]
    ├─ Create Tenant
    └─ Create User (OWNER)
    ↓
[Generate JWT Token]
    ↓
[Return Response]
    ↓
[Save to localStorage]
    ↓
[Redirect to Dashboard]
```

## Использование

### Регистрация нового тенанта

```typescript
// Frontend
const { register } = useAuth();

await register({
  tenantName: "Школа единоборств",
  email: "owner@example.com",
  password: "password123",
  firstName: "Иван",
  lastName: "Петров",
  phone: "+79991234567" // опционально
});
```

### API запрос

```bash
POST /api/auth/register
Content-Type: application/json

{
  "tenantName": "Школа единоборств",
  "email": "owner@example.com",
  "password": "password123",
  "firstName": "Иван",
  "lastName": "Петров",
  "phone": "+79991234567"
}
```

## Тестирование

### Успешная регистрация

1. Заполнить все обязательные поля
2. Ввести корректный email
3. Ввести пароль (минимум 6 символов)
4. Подтвердить пароль
5. Нажать "Создать аккаунт"
6. Ожидаемый результат: редирект на dashboard, авторизация

### Ошибки валидации

- Пустые обязательные поля → ошибка валидации
- Неверный формат email → ошибка валидации
- Пароль менее 6 символов → ошибка валидации
- Пароли не совпадают → ошибка валидации
- Email уже зарегистрирован → ошибка "Email уже зарегистрирован"

## Примечания

- Поддомен генерируется автоматически и не отображается пользователю
- После регистрации пользователь автоматически авторизуется
- Роль OWNER дает полный доступ ко всем функциям системы
- Email используется как уникальный идентификатор для входа
